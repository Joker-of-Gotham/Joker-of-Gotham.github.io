# 全站侧栏遮挡修正

## 范围与治理

| 项目 | 决定 |
| --- | --- |
| Work object | Task / 共用导航缺陷修复 |
| Risk | S1：本地布局与模态焦点调整，无远程写入或发布 |
| Quality | QA-L2：实际鼠标点击、键盘、跳转与历史返回回归 |
| Maturity | M3 本地验证目标，未部署 |
| Owner / DRI | Joker-of-Gotham / Codex |
| Review | 共用布局、交互及可访问性；不引入新系统，无独立 RFC / ADR 或敏感数据审查需求 |

用户提供截图并明确要求修正多页面侧栏；本次在已有授权内修改本地实现。

## 根因与修正

`body[data-scene-page] .site-shell` 为展示背景场景建立 `z-index: 2` 的堆叠上下文。侧栏原来在该容器里，虽声明 `z-index: 90`，仍低于挂在 `body` 的 `z-index: 70` 遮罩。遮罩的 backdrop-filter 将侧栏一起模糊，也拦截了侧栏链接和关闭按钮的点击。此问题在 Codex 浏览器实际复现，新增浏览器用例修正前也失败：关闭按钮中心的 `elementFromPoint` 命中遮罩。

在 `BaseLayout` 中把唯一的共用侧栏移到 `body` 直属层，与遮罩同级，保留既有导航布局及层级数值。首页与内页共用同一处组件。打开时将侧栏自身滚动位置恢复到顶部，并限制侧栏滚动向背景传递。

搜索打开前发出共用事件，先关闭侧栏、释放背景锁定并将焦点还给导航按钮，再由搜索接管。覆盖侧栏搜索入口和 Ctrl/Cmd+K，避免搜索关闭后焦点落在隐藏侧栏或留下遮罩。现有 Astro 页面切换清理继续生效。

## 验证

新增 `tests/e2e/sidebar.spec.ts`，直接覆盖 16 个页面地址，桌面/手机与明/暗主题共 64 组实际开关交互；同时覆盖侧栏链接连续跳转、浏览器前进后退、遮罩点击关闭、Escape、Tab 循环、短屏滚动与搜索切换。检查真实点击命中，不只检查 `aria-expanded`。

实际结果（2026-09-09）：

- `npm run check`：0 errors、0 warnings、3 条原有 hints。
- `npm run build` 与 Pagefind：成功，82 页。
- `npx playwright test tests/e2e/sidebar.spec.ts tests/e2e/route-scenes.spec.ts tests/e2e/library.spec.ts`：首轮 17 通过、1 失败。失败为测试预期研究计划页无查询参数，而页面正常添加 `expanded` 参数；修正断言为检查 URL pathname 后，单独重跑该历史导航用例通过。18 个相关用例均取得通过结果，生产代码未因此修改。
- 侧栏矩阵涵盖 16 个地址 × 2 个宽度 × 2 种主题 = 64 组开关；点击关闭、遮罩关闭、历史返回后重开、焦点回到按钮、搜索键盘切换、背景滚动位置保持均通过。
- Codex 浏览器复现修正前全屏模糊遮挡，修正后确认侧栏清晰且能实际点击“阅读”跳转，再次展开、点击关闭成功。
- `git diff --check` 通过；未提交、推送或部署。此前的“展开属性通过”不足以证明侧栏可交互，已由真实点击命中检查补足。
