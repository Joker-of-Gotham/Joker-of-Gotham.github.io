# 首页首屏构图稳定性

Task + 发布 Operation；S2 / QA-L3；M7 → 验证后发布 M8。Owner：Joker-of-Gotham；DRI：Codex。用户授权修正首页初始文字跳位，并将本人新增的研究内容与配图一同提交推送 main。范围为首屏 CSS、DOM 动画生命周期、对应回归和用户新增内容。无需独立 RFC 或专项评审，实施决策和验证记录在此。

## 原因与修正

旧首屏使用 75svh 的普通文档流；标题靠左，下一节会露出。只有 WebGL 开始发送导演进度后，`data-dom-motion` 才启用居中固定构图。模块、GPU 或网络加载期间因此会先出现错误布局，再跳到目标位置。

首屏现在由 CSS 直接保留完整视口，简介在场景初始化前使用绝对定位，初始化后沿用原来的固定定位；两种状态共享同一组水平、垂直和响应式构图规则。标题不被隐藏，也不等待 JS / WebGL 下载完成再显示。减少动画模式保留正常文档流，其余降级内容仍可阅读。

同时令 DOM 动画对同一根节点的重复生命周期通知幂等，避免 DOMContentLoaded、pageshow、astro:page-load 反复重置已经就位的构图。切页时释放监听，不改写离开页面的视觉布局。

## 用户新增内容

按用户要求包含 `research/具身智能/` 下三个层级的 `index.md`，以及 `public/assets/images/具身智能/数据飞轮/视频数据/learn_from_video-bridging_overview_new.png`。保留用户正文，只将图片引用从 Windows 相对路径修正为网站根路径，确保专题页能实际加载图片。其余文件与图片 SHA256 均与任务开始时一致。
